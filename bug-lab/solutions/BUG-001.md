# Solution BUG-001: fully shipped order stays partially shipped

**Symptom:**
- The final shipment of an order that already had a shipment, with no cancellations, leaves the order `partially_shipped` with 0 outstanding.
- A single full shipment from `confirmed` is still correct.
- Staff then see a shipment form with nothing left to ship. A retailer who asks to cancel gets "Nothing is left to cancel".
- The audit event for the shipment records `partially_shipped` as the new status.

**Cause:**
- The shipment status transition in `OrdersService.ship` keeps `PARTIALLY_SHIPPED` when the previous status was `PARTIALLY_SHIPPED`, even though `deriveFulfillmentStatus` returned `SHIPPED`.
- In Standard mode the database trigger `enforce_order_rules` would reject that state.
- A database marked for `BUG-001` exempts exactly this state, and nothing else, so the wrong status is really stored. See migration `20260930200000_bug_lab_marker`.

**Fix:** always persist the derived status (`status = derived`).

**Assertion (in `apps/api/checks/bug-lab.mjs`):**
1. Ship everything outstanding on `PO-000008`, which already has `SH-000001`.
2. Expect `shipped`, with 0 outstanding and 2 shipments.

Bug Lab observes `partially_shipped`, 0, and 2.
